# F09 评分与智驾报告（SCR）

> 需求来源：`requirement.md` §3.9、§4.7～4.8 ｜ 技术约定：`AGENTS.md` §6.5 ｜ 状态：已实现待验证（见 [PROGRESS](PROGRESS.md)）

## 1. 目标

把一局遥测转换成可解释的评分与报告：四项子分、总分、星级、称号、关键指标、历史对比与改进建议。评分必须是纯函数，同一遥测结果唯一。

## 2. 需求范围

SCR-01 指标采集、SCR-02 子评分、SCR-03 总分、SCR-04 星级、SCR-05 称号、SCR-06 报告、SCR-07 建议、SCR-08 下一关、SCR-09 效率信息（P1）、SCR-10 分享（P2）。

## 3. 指标

采集：距离、平均/最高速度、行程时间、碰撞、急刹、急加速、急促转向、AEB、接管次数/时长、跟车过近、最小跟车时距、变道尝试/成功/中止、不必要变道、无故停车、逆行、闯红灯、未让行、违规变道、超速、车道偏离、碰撞原因。

阈值：急刹 ≤ −4.0 m/s² 持续 ≥ 0.3 s；急加速 ≥ 2.5 m/s² 持续 ≥ 0.3 s；急促转向横向加速度 ≥ 3.5 m/s²；跟车过近 < 0.8 s 持续 ≥ 1 s；超速 > 限速 10 km/h 持续 ≥ 2 s。

## 4. 评分公式

```text
安全分 = 100 − 40×碰撞 − 8×接管 − 5×急刹 − 30×闯红灯 − 10×违规变道 − 10×跟车过近
舒适分 = 100 − 6×急刹 − 2×AEB − 3×急加速 − 2×急促转向
决策分 = 100 − 30×闯红灯 − 15×未让行 − 10×无故停车 − 10×逆行/错误车道 − 5×超速事件
变道分 = 100 − 25×变道失败/中止 − 10×不必要变道
总分   = round(0.40×安全 + 0.25×舒适 + 0.20×决策 + 0.15×变道)
```

补充：需要变道却零成功时变道分 ≤ 60；不需要变道且未发起则不扣分；子分截断到 0～100；碰撞/安全停车总分 ≤ 50、最高 1 星。

## 5. 星级与称号

| 总分    | 星级 | 称号     |
| ------- | ---- | -------- |
| 90～100 | 5    | 老司机   |
| 80～89  | 4    | 稳健型   |
| 70～79  | 3    | 合格     |
| 60～69  | 2    | 新手     |
| < 60    | 1    | 危险驾驶 |

## 6. 报告结构

```text
结果（通过/未通过 + 直接原因）
关卡 · 策略 · 是否接管
距离 / 平均速度 / 最高速度 / 行程时间
关键计数（碰撞、急刹、接管、闯红灯、变道）
四维子分 + 总分 + 星级 + 称号
与历史最佳对比
1～3 条改进建议
[重玩] [下一关] [返回主菜单]
```

## 7. 模块与接口

```ts
interface Telemetry {
  /* 计数与时序 */
}
interface ScoreResult {
  safety: number;
  comfort: number;
  decision: number;
  laneChange: number;
  total: number;
  stars: 1 | 2 | 3 | 4 | 5;
  title: string;
  passed: boolean;
  failReason: string | null;
  tips: string[];
}
function scoreRun(telemetry: Telemetry, level: LevelRule): ScoreResult;
```

- 纯函数：不读全局、不取时间、不随机。
- `src/game/scoring.ts` 只依赖遥测与关卡规则。
- 建议由最低子分与失败原因决定，模板集中管理。

## 8. 测试要点
